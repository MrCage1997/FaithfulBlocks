FaithfulBlocks 1.6.0-rc6 - Update-System
========================================

FaithfulBlocks verwendet ein öffentliches Update-Manifest im GitHub-Repository:

  https://raw.githubusercontent.com/MrCage1997/FaithfulBlocks/main/update.properties

Beim ersten Start wird automatisch folgende Konfiguration erzeugt:

  .minecraft/config/faithfulblocks-update.properties

Modi:
  mode=off
      Keine Update-Prüfung.

  mode=notify
      Prüft beim Start, lädt aber nichts automatisch herunter.
      Verfügbare Updates werden im Minecraft-Log gemeldet.

  mode=auto_download
      Prüft beim Start, lädt eine kompatible neue JAR per HTTPS herunter,
      prüft deren SHA-256 und ersetzt die alte FaithfulBlocks-JAR erst
      nach dem Beenden von Minecraft.

Konfiguration:
  mode=notify
  manifest_url=https://raw.githubusercontent.com/MrCage1997/FaithfulBlocks/main/update.properties
  connect_timeout_seconds=5
  request_timeout_seconds=15

Manifest:
  enabled=true
  version=1.6.0-rc6
  minecraft=26.3
  fabric_loader_min=0.19.5
  fabric_api_min=0.161.0+26.3
  download_url=https://github.com/MrCage1997/FaithfulBlocks/releases/download/v1.6.0-rc6/faithfulblocks-1.6.0-rc6.jar
  sha256=<64-stelliger SHA-256-Wert>

Sicherheitsregeln:
- Nur HTTPS-URLs werden akzeptiert.
- Eine andere Minecraft-Version wird niemals automatisch installiert.
- Fabric Loader und Fabric API werden gegen die Mindestversionen im Manifest geprüft.
- Die heruntergeladene JAR wird vor der Installation per SHA-256 geprüft.
- Bei Netzwerk-, Manifest- oder Hash-Fehlern startet Minecraft normal weiter.
- Die laufende JAR wird nicht während des Spiels überschrieben.
- Mit enabled=false kann der Update-Kanal vorübergehend deaktiviert werden.

GitHub-Release-Automatisierung:
--------------------------------
Nach dem Merge des GitHub-Workflows genügt für neue Releases:

1. Versionsnummer in gradle.properties ändern.
2. Änderungen nach main mergen.
3. Erfolgreichen CI-Build abwarten.
4. GitHub Release mit passendem Tag veröffentlichen, z. B. v1.6.0-rc7.

GitHub Actions baut anschließend automatisch die Release-JAR, lädt sie als Release-Asset hoch,
berechnet SHA-256 und aktualisiert update.properties auf main.

Weitere Details stehen in RELEASING.md.
